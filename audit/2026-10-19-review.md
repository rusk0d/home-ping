## 2. Findings

No high or critical issues in the code.

| ID | Sev. | Finding | Suggested fix |
|---|---|---|---|
| L1 | low | **Test depends on the machine's time zone.** `test_issue65` expects the server's local time to be Europe/Budapest (the migration converts local-time rows to UTC). In a UTC shell it fails with `migration: summer row -2 h (CEST)`. CI sets `TZ: Europe/Budapest` in `backend.yml`, so CI is fine, but a developer running `pytest` gets a false failure. | Set `os.environ["TZ"] = "Europe/Budapest"` and `time.tzset()` at the top of `tests/conftest.py`, then the test no longer depends on the shell. |
| L2 | low | **The cert watchdog's state is keyed by port, not host** (`_watch(f"cert_{port}", …)`, `server_checks.py`). Two hosts on the same port would share one state, so one host's "expires soon" push would be cleared by the other's "renewed". The config comment and `contracts/notifications.md` say "one host per port", so it's a documented limit, not a bug today. It becomes a bug the day a second host on 443 is added. | Key by the full `host:port` (`cert_<host>_<port>`), and update `notifications.md` (`device` field) in the same change. |
| L3 | low | **`check_sensors` runs its per-device queries every 30 s over the full raw retention** (`nodes.py`). Each device's `MAX(...)` scans its rows for 2 days (≈ 5,800 env rows at 30 s). The indexes `ix_readings_device_ts` and `ix_presence_device_ts` cover it, and the cost is small on this server, so this is a note rather than a fix. | If it ever shows up in profiling: add a `WHERE ts >= datetime('now', ?)` bound to the `has` part (it only needs "ever reported", so a longer window fits there). Nothing to do now. |
| L4 | low | **Web: the MQTT login is kept in `localStorage` with "Remember me"** (`web/app.js`, ~l.440). The MQTT user is read-only, and the CSP blocks inline scripts, so the exposure is small. The 10-16 review listed it as accepted. | Keep as an accepted risk; revisit if the page ever renders user-supplied text (it currently doesn't use `innerHTML`). |
| I1 | info | `reset_reason` (#228) is sent with every presence message (every 5 s on the radar node). The value only changes at boot, and the payload is 256 bytes, so it's fine. Older firmware without the field still works (`read_int` returns `None`). | None. |

## 3. What was checked and is fine

- **Sensor-silent alerts (#224):** the SQL placeholder order in `check_sensors` matches the tuple
  it's called with; the "alive" test stops an outage or a reboot from counting as a silent sensor;
  a failed push is retried (`if result:`); a cleared alert is only announced if the warning was shown.
- **Reset reasons (#228):** the code table in `store.py` matches ESP-IDF's `esp_reset_reason_t`
  (0–15). Brownout is 9, as the commit says.
- **Uptime (#226):** a missing uptime is `NULL`, so it no longer reads as a restart.
- **Auth:** credentials come from required env vars; both values are compared with
  `hmac.compare_digest`.
- **Web:** no `innerHTML` or `insertAdjacentHTML` in `web/app.js`; no inline scripts;
  `style-src 'unsafe-inline'` covers the inline `style=` attributes. `BROKER_HOST` in the CSP is
  filled in at install (README).
- **Contracts:** `mqtt.md`, `db-schema.md`, `api.md` and `notifications.md` describe the current
  code (reset_reason, RESTART text, cert push, coverage, BME280 retry). No drift found.
- **Firmware retry (#225):** the 30 s log message matches `ENV_INTERVAL`; the boot path still
  waits 1 s between the two attempts; `TEMP_OFFSET` is 0 after #167.
